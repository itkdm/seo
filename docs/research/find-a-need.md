# 寻找真实需求：从用户问题开始

产品点子可以来自灵感，值得做的产品则需要证据。观察目标用户反复提出的问题，通常比先 brainstorm 一堆功能更有效。

## 从哪里找问题

- **搜索结果**：自动补全、相关搜索和问答页面会呈现用户正在寻找什么。
- **社区讨论**：Reddit、垂直论坛、社交平台和专业社群里的提问与抱怨。
- **产品评论**：竞品的低分评论、功能请求和替代方案讨论。
- **工作流程**：人们用表格、复制粘贴或多个工具拼起来完成的任务。

## 记录证据，而不是记录点子

为每条线索记下用户是谁、触发场景是什么、问题多久发生一次、目前怎么解决，以及现有办法带来的损失。尽量保留用户原话，避免自己先替他们总结成产品功能。

## 下一步验证

挑出问题最具体、用户最容易接触的一类人，进行简短访谈或发布一个小型解决方案页面。关注用户是否愿意继续交流、留下联系方式、尝试产品或付费，而不是只看礼貌性的赞同。

::: tip 小原则
先验证“问题是否重要”，再验证“你的方案是否好用”。
:::
