# 一周做出 MVP：先验证最重要的假设

MVP 的目的，是用尽可能少的时间和资源验证产品最关键的假设。范围越小，越容易尽快见到用户并学到有用的东西。

## 先写清楚假设

用一句话描述：哪类用户，在什么场景下，愿意用什么方式解决问题？接着找出最不确定、验证失败会让项目停止的部分。这就是 MVP 首先应该验证的事情。

## 限定第一版

只保留完成一个关键任务所需的页面和流程。可以手动完成暂时无法自动化的后台工作；可以先用落地页、可点击原型或简单工具验证用户兴趣。对每个新增功能都问：没有它，核心假设还能验证吗？

## 发布后观察行为

邀请目标用户完成真实任务，观察他们在哪里停下、重复操作或需要帮助。记录完成率、完成时间、回访和付费意愿。收集到证据后，再决定是继续开发、调整用户群，还是换一个问题。

## 一周的节奏参考

- 第 1 天：定义用户、问题、成功信号。
- 第 2 天：和潜在用户交流，确认问题表达。
- 第 3–5 天：搭建最小的端到端体验。
- 第 6 天：邀请目标用户试用。
- 第 7 天：整理证据并决定下一轮行动。
